## 5. 缺陷清单（全部已定位根因）

### DEV-01 · 阻断级 · 规则永远无法创建

- **现象**：点「保存规则」后不跳转，提示「阶段二接口占位：未真实写入，草稿已保留在本页」；规则列表始终「共 0 条」。
- **定位过程**：先怀疑名称校验（`RuleService.ets:195` 要求 `name.trim().length > 0`），填名后仍失败；抓取保存瞬间 Toast 得到真实返回：`参数超出合法范围或类型不符（开关类命令的取值必须是布尔值）`。
- **根因**：`pages/RuleEdit.ets` `buildRule()` 里动作为 `{ command: POWER_ON, value: 1 }`，而 `RuleService.validateAction` 对 `powerOn` 要求 `typeof value === 'boolean'`，数字 1 被判 `INVALID_PARAM`。页面构造了服务层必然拒绝的对象。
- **修复**：`value: 1` → `value: true`。
- **回归**：`共 1 条 · 启用 1 条`，列表出现 `HotAutoLight / 已启用`（`lay_15_rule_created.json`）。

### DEV-02 · 误导性错误提示，掩盖真实失败原因

- **现象**：任何保存失败都显示「阶段二接口占位：未真实写入」，把 `INVALID_PARAM` 说成"功能没实现"，直接导致 DEV-01 被误判为"阶段二没做完"。
- **根因**：`save()` 的 else 分支写死阶段二占位文案，未使用 `CommandResult.message`。
- **修复**：改为 `this.saveNote = result.message;`。

### DEV-03 · 条件描述与实际保存内容不一致

- **现象**：阈值从 28 改到 18，`参数校验` 显示 18℃，但「条件 1：温度 大于 28℃」始终不变。
- **根因（两层）**：
  1. `conditionDrafts` 是 `@State string[] = ['温度 大于 28℃']` 的**初始化字面量快照**，阈值变更只更新 `threshold` 与 `validationNote`，不回写草稿；
  2. `ForEach` 的 key 生成器只含 `index`，内容变化不触发子组件重建。
- **修复**：`revalidate()` 内按当前 `threshold` 重建 `conditionDrafts`；key 改为 `'cond_' + index + '_' + draft`。
- **回归**：校验 16℃ / `条件 1：温度 大于 16℃` / `添加条件（温度大于 16℃）` 三处一致（`lay_22_cond_sync_fixed.json`）。

### DEV-04 · 页头标题在 387.7vp 折行留孤字

- **现象**：首页标题渲染为「智寓 · 宿舍控制中」+「心」，组件高度 198px（两行）。
- **根因**：`FONT_TITLE_LARGE` 固定 26fp，可用宽度仅 209vp，9 个汉字放不下，未设单行约束。
- **修复**：`maxLines(1)` + `minFontSize(18)/maxFontSize(26)` + `MIN_FONT_SIZE_FIRST` 自适应收缩；副标题加 `maxLines(2)` 防多行溢出。
- **回归**：标题高度 198px → **95px（单行）**（`lay_20_index_after_fix.json`）。

### DEV-05 · 环境概览四个数值折行

- **现象**：`50%RH` 显示为 `50%R`+`H`，`300Lux` → `300L`+`ux`，`50AQI` → `50AQ`+`I`；组件高度 152px。
- **根因**：20fp 固定字号，四宫格每格可用宽约 58vp，装不下 6–7 个字符。
- **修复**：同 DEV-04 的单行 + 自适应缩字号（下限 11fp）。
- **回归**：四个数值高度均为 57–69px **单行**（`lay_20_index_after_fix.json`）。

### DEV-06 · 成功率显示为裸比值

- **现象**：`规则执行成功率（真实日志派生）：1`（6/6 全成功时应为 100%）。
- **根因**：`StatisticsService.successRate()` 返回 0~1 比值，页面直接字符串拼接。
- **修复**：`(value * 100).toFixed(1) + '%'`。
- **回归**：显示 `0.0%`（当前无执行记录，格式正确）。

### 曾误判、经复测排除的一项

**规则列表页"顶部约 480px 异常空白"**：首次抓取时页头位于 y=542，与设备页/环境页的 y≈170 差异巨大，一度判定为布局缺陷。随后同页多次复测得到 y=542 / 529 / 264 三组不同值，确认是**路由转场动画尚未结束时抓取的中间帧**，不是布局问题。此项**不作为缺陷记录**，特此更正。

| `scripts/capture.sh <name>` | 抓当前屏截图 + `uitest dumpLayout` 组件树，落到 `screenshots/` 与 `evidence/device/` |
| `scripts/layout.js <json>` | 解析组件树，输出「类型 / 像素边界 / 换算 vp 宽高 / 文本」 |
| `scripts/btn.js <json> <text> [nth]` | 按文本定位控件，返回中心像素坐标 |
| `scripts/tap.sh <text> [nth]` | dump → 定位 → `uiInput click`，一条命令完成点击 |

关键坑位（后续复现者会踩）：
1. Git Bash 会把 `/data/local/tmp/x` 当本地路径重写，必须 `export MSYS_NO_PATHCONV=1`；
2. `hdc file recv` 的本地路径要**先 cd 到目标目录再用相对文件名**，传绝对路径会被拼到 cwd 后面；
3. 软键盘会遮挡底部按钮，`dumpLayout` 里根本看不到「保存规则」，需先 `keyEvent Back` 收起；
4. 视口底部按钮可能被裁切导致点击不命中，先滚动再点。

## 10. 结论

应用在 HarmonyOS API 17 手机模拟器（387.7vp × 836.9vp）上**可以安装、可以启动、六个业务模块可以真实操作**，且设备控制、参数越界拒绝、环境采样、规则触发、场景切换、图表统计、数据导出均为**真实业务逻辑**，未见预设假效果。

本次验证的最大价值是发现了 **DEV-01 这个阻断级缺陷**——在手机上此前**完全无法创建任何规则**，而该问题在任何构建门禁和静态走查中都不可能暴露（`BUILD SUCCESSFUL`、类型检查全绿）。它只在真机/模拟器上点一次「保存规则」才会现形。

**当前最关键的未通过项是持久化**：退出即丢数据。该项已设计定稿但未编码，属 ST-04，必须在阶段四完成后重跑 4.9 的 8 步验收，才能宣称通过。
